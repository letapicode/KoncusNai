# Workbench dictation input and feedback

Dictation input and history navigation have separate ownership. Saving a new record does not select it. Sidebar query results restore selection with activation forwarding suppressed; explicit selection or Enter can open history. New Workbench records contain the individual transcription, rather than cumulative composer snapshots. Existing history is not rewritten.

A recording captures its editor, selection, draft revision, dictation session, and conversation identity. Insertion uses the editor's change block and an independent undo unit. Intervening edits, a changed editor/conversation, or loss of foreground ownership reject automatic insertion and retain the transcript for recovery. This intentionally conservative policy does not guess where words belong after a draft changes.

The global pipeline captures an application-owned target only when the actual foreground window and focused control are the Workbench composer. Its dispatcher-owned insertion avoids Windows UI Automation/clipboard insertion into our own editor. External targets retain the existing Windows insertion and safety policies. Once a composer target was captured, a stale result cannot fall back into another application. Microphone ownership is shared across production capture services, including the chunked global capture path.

Workbench transcription publishes text before awaiting history persistence. The operation lease still tracks the save, and shutdown awaits that operation before disposing history services. A completed transcript is saved without the recording cancellation token; storage failure remains distinct from transcription/insertion failure. The last-dictation recovery cache remains available independently of a failed durable write.

Workbench microphone feedback uses only the existing focus-safe Windows recording/transcribing/completion overlay for routine dictation. Actionable dictation failures appear above either composer and remain until dismissed or a new recording starts; successful insertion with a failed history save has its own recovery notice. Clearing an outcome also clears its cached text, so later renders cannot revive it. The shared indicator respects Windows client-area animation preferences at presentation time. Reply action buttons use explicit transparent chrome, preserve keyboard focus indication, and keep stable tooltips; the clipboard callback reports success or failure.

Model installation, runtime readiness, and unknown status are distinct. Readiness probes carry a request version and model-selection revision; stale results and completions after disposal are rejected. Failed runtime checks retain established managed-model installation state. Setup rechecks managed installation before downloading. Ollama remains unknown while unreachable and requires its existing trust review before use. Local GGUF existence is separate from verified runtime/model usability; a partial or unverified file can require repair.

Inline Settings uses existing Workbench zoom and synchronizes its draft so later autosaves do not undo presentation zoom. Standalone Settings zoom is local to that window. Active shortcut capture retains its keystrokes and can be cancelled with Escape or loss of focus. Settings content permits horizontal scrolling where necessary at increased zoom.

## Follow-up presentation and navigation

Actionable model notices and setup progress live in a reserved strip above the compact or expanded composer. Routine Idle/Ready labels and top-corner duplicates are suppressed. Unknown, missing, stopped, failed-check, and trust/repair states retain appropriate actions; selecting a model only checks readiness. A check disables submission while pending. The UI and submission command both require verified installation/runtime readiness, including local greeting/calendar replies. Loading history with a different model resets readiness and its selection revision. Runtime failure still refreshes state through the existing failure path.

Settings owns Home/End and Ctrl+Home/End through a shared preview handler, before the ScrollViewer can interpret Home/End as horizontal navigation. Text fields, passwords, selectors, menus, sliders/range controls, modifier combinations, and active shortcut capture keep ownership of their keys. NumLock-off keypad keys arrive as Home/End; numeric input is not remapped.

Paper mode scopes its palette across the Workbench, including inline Settings, and draws one full Workbench background texture. The bounded page border/shadow is removed. Inputs and focus/selection boundaries remain distinct, and normal theme resources return when Paper mode is disabled. Sidebar-specific rows reduce padding and the reserved action height without changing the global history style.

## Composer alignment and history safety corrections

The compact composer and every notice above it share one width resource through their common container. The former notice/composer limits of 960/900 caused the visible offset. Import status also fills the available width instead of forcing a 720-pixel panel. Expanded notices share their editor's grid. Rendered bounds checks cover 1,000- and 2,400-pixel window widths, both sidebar states, and 80%, 100%, and 150% zoom; additional render captures use a 125% bitmap DPI scale. These are layout/render checks, not physical monitor DPI validation.

History results explicitly declare whether visible feedback is needed. Successful loads leave the model/recovery notice alone; selection/focus and a polite accessibility item status remain available. Context-menu selection suppresses activation for both clearing and selecting. Already-selected rows still open through explicit mouse or Enter activation. While a row menu is open, refresh restores its target identities rather than the active conversation's selection; a missing target closes the menu. Menu selection never loads the row.

Composer changes notify history tracking even when programmatic synchronization suppresses normal UI events. A pristine history load remains pristine, while later typing, replacement, undo, clearing, dictation insertion, and imports protect the draft. Delayed deletes compare the loaded draft identity before clearing. Save/rename results also check their original selection or conversation before updating the current view. Deleting an inactive chat no longer resets the active conversation, and deleting an active chat preserves unsent text. These protect against switching targets or editing while storage is pending.

A combined day with several dictations cannot save its combined text into one constituent. The disabled Save tooltip and command result direct users to edit an individual entry in History. A day with one explicit record can still be edited. No history content, record identities, or timestamps are migrated or deduplicated.

Expanded submission checks the same readiness and operation conditions before collapsing. Synchronization avoids identical text assignments and never focuses the hidden compact editor. Rejected pointer or Enter submission preserves expanded text and selection. Programmatic history replacement/clearing also synchronizes an open expanded editor.

The microphone has a local transparent 36-pixel icon-button template. Hover changes foreground only; keyboard focus has a visible rounded outline. Recording keeps the stop glyph, tooltip, and accessible name. Ordinary theme and Paper resources supply its colors; the style does not change other buttons.

If startup feedback fails or is cancelled after device acquisition, cleanup stops capture without the cancelled token and clears its overlay. A partially acquired device retains the shared capture lease until stopped. Production overlay presenters coordinate presentation ownership only: a new recording retires the previous indicator, so older completion or auto-hide cannot hide the newer recording. Capture, inference, and history saving remain independent; no pipeline-wide lock, extra runtime probe, retry, or artificial delay was added. Existing provider worker-start coordination is unchanged.

Recovery notices retain their own transcript and expose Copy dictation, independent of the shared last-dictation cache. Clipboard failure keeps that same transcript available for retry. Completion-overlay failure is observed without skipping the history write or misreporting successful transcription as a transcription failure. Controlled tests cover a chunked capture starting during another transcription, a pending history write while the shared cache changes, and old overlay completion/hide after a newer recording.

The presentation-only coordinator was measured with identical warmed no-op presenters, 20,000 calls per sample. The last two samples measured 0.001 microseconds/call directly versus 0.064 microseconds/call through ownership coordination. This establishes only synthetic coordination overhead; it excludes Windows overlay dispatch, microphone startup, worker inference, and storage. No real-device performance baseline was collected.

The render fixture loads application theme resources through a plain WPF Application, avoiding accidentally queued production startup and a competing diagnostics logger. It disposes the composition's logger. Public API/dependency baselines remain unchanged.

## Microphone insertion and recovery follow-up

The production reducer disabled the compact editor for the transcription operation while both captured-target validation and the editor insertion path required an enabled editor. Insertion still owned the transcription lease until history persistence completed. The reducer now permits editing specifically for RecordingStart/Transcription leases; import and Settings leases remain exclusive. The expanded editor follows the same projection. Captured text/revision, conversation, editor identity, foreground ownership, Settings visibility, enabled/read-only state, and shutdown checks remain intact. Integration regressions host both actual editor controls, exercise the command controller, operation lease, and reducer, and check insertion before persistence, caret replacement, and undo.

Transcription progress now renders after the controller enters Transcribing. The neutral microphone uses one circular local focus border, with no shared rectangular focus adorner. Its stop glyph has a theme-aware muted circular background only while recording. No animation was added; the stop glyph, action name, and shared overlay convey state without color alone.

Insertion outcomes carry separate draft-change, unavailable target, conversation/editor change, foreground loss, shutdown, and unexpected-failure reasons. User notices distinguish insertion from persistence. Copy and Dismiss are separate. Window-lifetime recovery stores each transcript under its own identity, independently of the latest-dictation cache. Dismiss removes a saved recovery notice; unsaved entries remain accessible through Recover dictation. Starting another recording and unrelated feedback hide the active notice without deleting those entries. Successful copying acknowledges only the selected record. Clipboard failure preserves recovery. A press retains its record identity across replacement; stale actions and queued timer ticks cannot clear a newer persistent notice. Recovery menus are reused across unchanged renders rather than rebuilt during typing/model refresh.

Recovery is memory-only when storage has failed. Copy unsaved entries before closing the Workbench or exiting the app; this correction does not claim a durable backup when persistence is unavailable. Current settings provide history management, not a history-disable switch. About and the user/implemented-feature guides now describe this actual behavior. Reading Studio Help remains dedicated to Reading Studio. The code-wrap tooltip is “Wrap long lines.”; wrapping still copies original source whitespace and line breaks.

No capture/inference scheduling delay, runtime probe, retry loop, or pipeline lock was added. Moving the existing progress callback follows the actual state transition; device performance still requires comparable live measurements. Synthetic ordering tests do not establish microphone or cold/warm inference latency.
